# Logging Guide & Debugging Strategy

This application utilizes **Spring AOP (Aspect-Oriented Programming)** to automatically track every method call in your Controllers and Services.

To prevent performance degradation and log bloat in production, this AOP tracking is controlled via the `LOG_LEVEL` environment variable.

## How it works
- **`LOG_LEVEL=INFO` (Production Default)**: The AOP tracking is completely silent. Only explicit `log.info()` statements and `ERROR` exceptions are printed to Dozzle.
- **`LOG_LEVEL=DEBUG` (Debugging Mode)**: The AOP tracking activates. Every single controller and service method will log exactly when it was entered, what arguments it received, when it exited, and exactly how many milliseconds it took to execute.

## How to enable full AOP Logging (Debugging Mode)

If you have a production issue and need to see the exact execution trace of the app:

### If running locally
1. Open your `.env` file.
2. Change `LOG_LEVEL=INFO` to `LOG_LEVEL=DEBUG`.
3. Restart your application (or run `docker-compose down && docker-compose up -d`).

### If running on EC2 (Production)
Since your `.env` file is generated by GitHub Actions using your `PRODUCTION_ENV` secret:
1. Go to your repository on GitHub.
2. Click **Settings -> Secrets and variables -> Actions**.
3. Edit the `PRODUCTION_ENV` secret.
4. Find the line that says `LOG_LEVEL=INFO` and change it to `LOG_LEVEL=DEBUG`.
5. Save the secret.
6. Create a new Release on GitHub to trigger the deployment.

Your server will restart within 30 seconds. You can then open Dozzle (`http://<EC2-IP>:9999`) and you will see a massive, detailed trace of every single action happening in the app!

*Don't forget to change it back to `INFO` when you are done debugging to save server resources!*
